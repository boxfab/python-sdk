# Upstream

The BoxFab Python SDK is derived from the open-source
[E2B Python SDK](https://github.com/e2b-dev/E2B/tree/main/packages/python-sdk) and includes
modifications for BoxFab's sandbox infrastructure. BoxFab is an independent project and is not
affiliated with or endorsed by E2B.

## Pinned source

- Repository: https://github.com/e2b-dev/E2B
- Path: `packages/python-sdk`
- Release: `e2b` 2.62.0 (tag `@e2b/python-sdk@2.62.0`)
- Commit: `3a904178b2f1d1c40fd2ba1c2ad9a10f43896bf1`

2.62.0 was the newest release when this fork was made, and the exact version our deployment's
benchmarks and smoke tests already run against unmodified, so it carried the least risk.

## How the code is produced

`boxfab/`, `tests/`, `pytest.ini`, `LICENSE-E2B` and `CHANGELOG-E2B.md` are generated by
`scripts/sync_upstream.py` from the pinned commit and are never edited by hand. The script copies
the upstream package and applies a fixed, asserted set of rewrites:

| Change | Why |
|---|---|
| package `e2b` → `boxfab` (directory, imports, module paths) | distribution and import name |
| every `E2B_*` variable the SDK reads → `BOXFAB_*`, no fallback | a BoxFab install must never pick up an E2B key or domain, nor send one elsewhere |
| default domain `e2b.app` → `boxfab.io` | BoxFab's domain; no implicit calls to E2B's service |
| product name in docstrings and comments `E2B` → `BoxFab`, `e2b.dev/docs` links → `boxfab.dev/docs` (lines that use the `E2B` alias as code are left alone; the number of changed lines is asserted) | the SDK's own documentation names the product it talks to |
| `importlib.metadata.version("e2b")` → `"boxfab"`, `publisher` header, User-Agent `boxfab-python-sdk/<ver>` | the renamed distribution would otherwise fail on import |
| missing-key error message points to the BoxFab dashboard | actionable message |
| client class `E2B` → `BoxFab` (`E2B` kept as an alias) | branding; existing code ports by changing the import |
| upstream unit tests asserting the `e2b.app` default use ours | follow the default change |

Deliberately unchanged:

- `boxfab/sandbox_domains.py`, the list of E2B-hosted domains. For a domain on that list the SDK
  sends sandbox traffic to a shared `sandbox.<domain>` host with routing headers; for any other
  domain (ours) it uses `https://<port>-<sandboxID>.<domain>`, which is what our client-proxy
  serves. Adding our domain to the list would change routing.
- Shell variables inside generated template build steps (`E2B_HEREDOC_*`, `E2B_EXIT`), and
  wire-level identifiers (headers such as `E2b-Sandbox-Id`, the `e2b_` API-key prefix, generated
  API and envd clients): they are protocol, not branding.
- The dependency `e2b-dockerfile-utils` (Apache-2.0, published on PyPI by E2B) is used as is,
  not vendored or renamed.

## Verification (2026-11-01)

The deployment runs the open-source E2B runtime with server-side patches only (worker discovery,
team self-endpoints); the SDK-facing protocol is unchanged, and unmodified `e2b` works against it
with `E2B_DOMAIN` set. The same live suite (`integration/test_live.py`) was run with both SDKs
against `sandd.contextfab.io`, using a test team's key:

| Area | `e2b` 2.62.0 | `boxfab` 0.1.0a1 (source) | `boxfab` 0.1.0a1 (built wheel, clean venv) |
|---|---|---|---|
| create / run / kill, context manager | pass | pass | pass |
| stdout, stderr, non-zero exit code | pass | pass | pass |
| command timeout | pass | pass | pass |
| background process + public port URL | pass | pass | pass |
| files: write/read text and bytes, list, exists, remove, missing file | pass | pass | pass |
| signed upload / download URLs | pass | pass | pass |
| connect by ID, list by metadata | pass | pass | pass |
| pause / resume with state | pass | pass | pass |
| set_timeout, get_info | pass | pass | pass |
| invalid key (and key not echoed), unknown sandbox ID, unreachable domain | pass | pass | pass |
| cleanup after an exception inside `with` | pass | pass | pass |
| async: 5 concurrent sandboxes | pass | pass | pass |

The `boxfab` runs had `E2B_API_KEY` and `E2B_DOMAIN` set to E2B's service to confirm they are
ignored. Connection tracing during the run showed TCP only to the deployment's edge address
(port 443) and the local DNS resolver. TLS verification is upstream's default (on). Upstream's
offline unit tests: 485 pass after the rewrites; BoxFab's own config tests (`tests_boxfab/`): 8
pass. Not yet verified on BoxFab: template builds, volumes, secrets, MCP, IAM tokens, network
rules, git helpers, PTY, filesystem watch.

## Updating

1. Pick the new upstream release tag and put its commit SHA in the "Commit" line above.
2. `python scripts/sync_upstream.py` (or `--src <checkout>`). A failing rule means upstream moved
   the code it targets: adjust the rule, not the generated files.
3. `git diff` the result, run the unit tests and the live suite (`integration/`), update
   `CHANGELOG.md`.
